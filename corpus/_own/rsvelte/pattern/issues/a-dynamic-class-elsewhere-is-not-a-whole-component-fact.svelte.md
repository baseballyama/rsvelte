# `a-dynamic-class-elsewhere-is-not-a-whole-component-fact.svelte`

**Issue:** css-prune probe

`is_nesting_compound_unused` opened with `if ctx.has_dynamic_classes { continue }` — a WHOLE-COMPONENT flag — so a single `class={expr}` anywhere in the template disabled the `&.x` check for every rule in the file. Upstream decides per element: an element whose `class` value it cannot enumerate matches any class selector, and every other element still constrains. The distinction is invisible in a two-element reduction and universal in real components, which is why the huly and musicat entries sat in the under direction with a shape that reduces to three lines. The per-element predicate now carries the openness (`has_spread`, or a dynamic `class` / `id` attribute on THAT element), the same test `structural_element_matches_compound` already used. The `.host { &.dragging }` control is the part worth reading: it must NOT be reported, because the `class={`opaque ${value}`}` div satisfies `.host` and `.dragging` at once — so the anchors that discriminate are tag-pinned (`container`, `section`), which an unresolvable `class` cannot make an element into. Measured on the 80-entry warning ratchet: entries with a code divergence 8 -> 7, the under direction 6 -> 5. Ablated, this file reports nothing at all where official reports two, and the five controls are unchanged in both arms.
