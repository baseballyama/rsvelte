# `a11y-label-comment-counts-as-content.svelte`

**Issue:** warning probe

Upstream's `has_content` (`2-analyze/visitors/shared/a11y/index.js:791-822`) has arms for `Text` and for `RegularElement` / `SvelteElement` and ends `// assume everything else has content` — so a **Comment** child reaches that fall-through and counts as content, which is what keeps `<button><!-- icon --><svg/></button>` out of `a11y_consider_explicit_label`. rsvelte's port added an explicit `TemplateNode::Comment(_) => {}` arm that skips it. The over-report is not exotic: an icon-only `<button>` or `<a>` with a comment naming the icon is 4 of the 80 warning-ratchet entries, across cpi-ide, headscale-ui (x2) and svelte-put. The file's second half is the control, because the fix is a DELETED arm and a port that also stopped warning on a genuinely empty element would pass the first half: an empty `<button>`, a `<button>` holding only an empty `<span>`, and an icon-only `<button>` with no comment must all still warn, and one with text must not. Measured on the 80-entry ratchet: entries with a code divergence 19 → 15 with the code's bucket emptied, the under direction unmoved at 6; on a 14-cell content-kind grid against the official compiler, 10/14 before and 14/14 after.
