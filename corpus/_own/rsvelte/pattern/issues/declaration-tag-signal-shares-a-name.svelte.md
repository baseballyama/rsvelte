# `declaration-tag-signal-shares-a-name.svelte`

**Issue:** corpus — `svelte-heroicons/src/routes/+page.svelte` ([#4791](https://github.com/baseballyama/rsvelte/pull/4791))

A `{const x = $derived(…)}` / `{let x = $state(…)}` declaration tag lost its `$.get(x)` reads, updates and component-prop getters on the client whenever another binding anywhere in the component had the same name: the program-level `add_state_transformers` pass registers transforms from the flattened root scope, which keeps one binding per name, and that one was the `{#each}` context or the function parameter. Upstream's `DeclarationTag` visitor runs `add_state_transformers` over the tag's own scope, so the visitor now registers the transform for each declared identifier, resolved by its declaring position. The cells are the three collisions found: an `{#each}` context (`name`, `count`), a parameter of an instance-script arrow (`name`), and a plain instance binding shadowed by a `$derived` tag (`label`). A `$state` tag that shadows an **instance** binding is deliberately absent: the text pipeline lowers its declaration from that instance binding (`let v = 1` where upstream writes `$.state(1)`), so the visitor leaves its reads consistent with that declaration, and the cell diverges on both arms. Server output is identical on both arms; client and client-dev diverge without the fix and match with it.
