# `custom-element-parent-traversal.svelte`

**Issue:** corpus residue

A custom element takes its attributes through properties, so upstream marks its ANCESTOR fragments dynamic — but only when it has one: `2-analyze/visitors/RegularElement.js` gates that `mark_subtree_dynamic` on `node.attributes.length > 0`. rsvelte's `has_dynamic_children`, which stands in for `metadata.dynamic` when deciding whether a PARENT is static, dropped the attribute half, so a bare `<media-a></media-a>` made every ancestor emit a `$.child` / `$.sibling` / `$.reset` chain that official replaces with nothing at all — the template string and its flags agreed throughout, so only the traversal diverged. The element's OWN `is_static_element` is a different question that upstream gates on no attribute count, so that check stays unconditional. Four blocks are controls that must keep their traversal: a dashed name with a static attribute, the `is=` spelling on a plain tag name, an attribute-free custom element whose fragment is dynamic on its own account (`{n}`), and a plain `<i>` that never traverses either way. The nested attribute-free pair pins that neither level may traverse, and the trailing `$.next(4)` skip count moves with the rule.
