# `a-has-on-a-parent-level-kills-the-chain.svelte`

**Issue:** css-prune probe

`is_parent_chain_unused` decides whether an enclosing level can match by scanning its subject compound for classes, ids and tags, and its `PseudoClassSelector` arm treats everything but `:global` as constraining nothing. A parent whose ONLY reason to be unused is its `:has()` therefore looked alive, so it was reported while every rule nested inside it survived — the parent and the child disagreeing about the same selector, in one output. The chain check now runs `is_has_selector_unused` on the level's own relative selectors first. Two of the three surviving corpus entries were this, and neither looked like the other from the divergence: `mathesar`'s `.entity-switcher:has(button:focus) { .trigger { … } }` (the `<button>` is rendered by a component, so the component's own tree holds none) and `huly`'s `#ui-root:has(.workbench-container) .antiStatusBar { .second-row { … } }`, which had been filed as a `#2535`-shaped two-compound-parent problem and is not one. The controls are a `:has()` the component satisfies (whole chain kept) and a genuinely dead child under a live `:has()` parent (still reported on its own), because a fix that let any `:has` kill the chain passes the first half. Measured on the 80-entry warning ratchet: entries with a code divergence 3 -> 1. Ablated, this file reports four of the eight and its CSS stops matching.
