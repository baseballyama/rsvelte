# `class-and-function-declarations-bind-a-name.svelte`

**Issue:** shadow probe

A `class v {}` and a `function v() {}` bind `v` in the enclosing block exactly as `let v` does, and the two client shadow registrars each knew a different half of that: `ast_state_transform.rs` had a `visit_function` arm for a function declaration and no class hook at all, and the template walker's `register_block_local_vars` read `JsStatement::VariableDeclaration` and nothing else. So `class v {}` inside a function read `typeof $.get(v)` on both paths, and a `function v() {}` inside a template handler did too. The two ports are the reason the file carries the same shapes twice — an instance-script function body and an event-handler arrow — and a prop name (`w`) beside the `$derived` name (`v`), because the prop half answers through a different set again. `sibling()` is the positive control: it reads the same two names from a function that declares neither, so a fix that leaks the declaration out of its own scope turns it red. Ablated one hunk at a time over the 96-comparison grid: 4 for the instance-script hook, 8 for the template one, 12 with both removed. 0 of 34,728 corpus entries move.
