# `typescript-omits-the-import-fields-acorn-always-writes.svelte`

**Issue:** parse-ast probe

The same fields under `lang="ts"`, where **the answer is the opposite one**, because upstream runs a different parser: acorn always writes `attributes` and `options`, acorn-typescript writes `attributes` only where a `with` clause exists, spells a dynamic import's second argument as an `arguments` LIST, and omits both keys when there is none. So the rule is not "emit the field" but "emit what the parser upstream ran emits" — `estree_module_kind` already says exactly this one line above, for `importKind`/`exportKind`, and the family is the rest of that sentence. A sweep of 41 JS constructs hosted in a plain `<script>` and in `lang="ts"` is what found it: five node shapes differ on that axis alone, and only two of them had a corpus carrier, so a collected corpus could never have enumerated the class. On that 164-cell grid the tree went from 32 cells carrying 20 distinct keys to 12 carrying 6. The `import type` row is not decoration: `importKind` is `Some("type")` there while the program is TypeScript either way, which is what makes `import_kind.is_some()` a sound test for "which parser ran" rather than a guess. One member of the family has **no carrier any component can hold**: `export default` is illegal in every Svelte script, so the `exportKind` acorn-typescript stamps on it is reachable through `parse()` and never through `compile()` — it is pinned by `crates/rsvelte_core/tests/import_export_parser_shapes.rs` instead, which carries one independently-failing test per rule in the family, because a single "all shapes agree" assertion is satisfied by every rule but the broken one. The same sweep found one more defect, closed by the row below: `export * from` was dropped from `parse()`'s program body entirely, while `compile()` kept the statement. Measured: six keys per axis pre-fix, zero post-fix, with compile output byte-identical on all four targets.
