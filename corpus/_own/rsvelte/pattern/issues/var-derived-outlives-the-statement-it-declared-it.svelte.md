# `var-derived-outlives-the-statement-it-declared-it.svelte`

**Issue:** shadow probe

`var` is function-scoped, and `NestedRuneLower` recorded a derived binding in `self.derived.last_mut()` — the frame `visit_statement` pushes around **every** statement — so `if (flag) var value = $derived(1)` died with the `if` and the following `return value` was never rewritten to `value?.()`. The struct already carried `Some(is_var)` per binding for the `?.()` spelling; it was the frame CHOICE that ignored the kind. Server only, and only where the read is a SIBLING of the container: `switch`-case and a labeled block already matched because their read sits inside the frame the declaration landed in, which is why those two are in this file as controls rather than as rows. The defect became reachable through `d5738595e`, which stopped `collect_block_decl_names` from putting a `var` in the per-block shadow frame and started hoisting it to the function frame instead — the server's read-wrap pass had been doing this work by accident, on names it should have been treating as shadowed. Two positive controls in the other direction: a plain `var value = 11` must stay `typeof value` (a fix that just stopped hoisting `var` names passes every row and breaks this one), and a `var` inside a nested function must not leak out. Measured on a 4-target × 7-declaration × 9-container grid against the official compiler: 572 of 576 identical with the fix, 524 with it ablated, so 48 cells move and none moves the other way. The 4 residual cells are `derived-let` × `switch-case-bare` on the client, which is upstream #3420 and diverges in both arms.
