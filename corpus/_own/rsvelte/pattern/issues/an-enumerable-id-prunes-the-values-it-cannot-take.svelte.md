# `an-enumerable-id-prunes-the-values-it-cannot-take.svelte`

**Issue:** css-prune probe

The other direction of `a-dynamic-id-matches-any-id-selector.svelte`, and the same asymmetry: upstream runs one chunk expansion over `get_possible_values` for every attribute, with `is_class` deciding only whether array/object expressions are inspected, while rsvelte's `id` branch called **any** expression indeterminate. So `id={cond ? 'a' : 'b'}`, `id={'a' || 'b'}` and `id={'lit'}` kept every `#id` rule official prunes — an over-keep, costing CSS size and a `css_unused_selector`, not rendering. The same three shapes spelled with `class` already matched, which is what makes it the attribute and not the expression. **The two directions cannot share a file**: `has_dynamic_ids` is component-wide, so a single genuinely dynamic `id={free}` anywhere suppresses the pruning half entirely — the first version of this repro carried both and reported no warnings at all. The indeterminate direction stays pinned by the sibling file. Pre-fix this file emits one of the two expected warnings, not zero: `#never-produced + .anchor` already pruned through the per-element sibling matcher while the simple `#never-produced` did not, so the two ports are visible inside one file.
