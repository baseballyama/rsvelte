# `bind-this-block-kinds-for-non-reactive-update.svelte`

**Issue:** warning probe

Upstream decides `non_reactive_update` for a `bind:this` by walking the reference path back from the `BindDirective` for an `IfBlock` / `EachBlock` / `AwaitBlock` / `KeyBlock` (`2-analyze/index.js:757-767`) — a `SnippetBlock` is not one of them. rsvelte replaced that walk with a precomputed boolean fed by `block_depth`, whose four incrementing visitors are If / Each / Await / **Snippet**: so `{#key}` under-warned and `{#snippet}` over-warned, in one substitution, in opposite directions. The third defect is on the other axis: a Component's `bind:` never reaches `bind_directive::visit` at all (it goes through `walk_bind_expression` from `shared/component.rs`, which only sets an `in_bind_this` suppression flag), so a component in ANY of the four blocks was silently missing. Reducing a path walk to a counter is what merged the three: none of them is visible unless the grid crosses block kind WITH host, which is why this file carries both. Measured on the 80-entry warning ratchet: entries with a code divergence 24 → 19 and the `non_reactive_update` bucket 8 → 3, all three survivors over-reporting; on a 12-cell host × wrapper grid against the official compiler, 7/12 before and 12/12 after. The ablated arm of this file reports the four missing warnings AND the spurious `snippet_element`, so a fix in one direction alone leaves it red.
