# `html-comment-svelte-ignore-before-a-script-tag.svelte`

**Issue:** warning probe

An HTML comment immediately before a `<script>` silences its codes for the whole script: upstream parks it on the Program as `leadingComments` (`1-parse/state/element.js:349`) and its generic `_` visitor pushes them for the subtree. rsvelte built `ProgramMetadata.leading_comments` and never read it in the analyze walk — and on the compile path never even built it, because `defer_script_parse` re-parses the script through `ensure_script_parsed_retained`, which passed a hardcoded empty comment list. That is 19 of the 78 measured warning-ratchet entries. The other half of the file is the NEGATIVE, and it was a live over-suppression on the style path: `pending_leading_comments` accumulated every comment in the file and was cleared only on parser reset, while upstream's backward scan stops at the first sibling that is neither a Comment nor whitespace-only Text — so a `<!-- svelte-ignore css_unused_selector -->` with a `<div>` between it and the `<style>` block silenced the block anyway. Both halves are pinned here because a fix for either one alone leaves the other wrong in the opposite direction, and the two are reported through the same accumulator. Measured on a 24-case probe against the official compiler: 24/24 with both halves, 20/24 with the sibling-stop rule ablated (4 cells, 2 of them the pre-existing style over-suppression) and 15/24 with the analyze-side read ablated (9 cells).
