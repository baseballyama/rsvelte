# `is-branch-is-not-nested-under-its-own-rule.svelte`

**Issue:** css-prune probe

`&:is(button)` means `&button` — one compound — but rsvelte judged the branch through `is_is_inner_selector_unused`, which recursed into `is_complex_selector_unused` carrying the SAME `ctx`, preludes included, so `button` was evaluated as if it were nested UNDER `.tile`. Its own doc comment says the branch is judged "on its own (no enclosing-chain context)"; the context was still there — a fidelity claim in a comment, which is where this class hides. Every `:is()` / `:where()` in a compound with `&` was pruned as a result, `:is(*)` included, while `:not()` and `:has()` were exempt by name and a top-level `.tile:is(button)` was right because there were no preludes to leak. The fix substitutes each branch into the enclosing compound (`substitute_is_branch`, whose `BranchHost` arm existed with no caller) and answers unused iff EVERY substitution is: the original is reachable exactly when one branch's substitution is. Measured on the 80-entry warning ratchet: entries with a code divergence 14 -> 12, the over direction 8 -> 6; on this file's 23-cell grid against the official compiler, 12/23 before and 23/23 after, with emitted CSS byte-identical on all 23. Two rows are here because a cheaper fix passes without them. Clearing the preludes for the branch check alone scores 18/18 on a grid of one-rule components and REGRESSES a component holding `&:is(div)` beside `&:is(div, .zz)` when a `<div>` exists elsewhere: the branch then reads as reachable in isolation, the compound reads as used, and the report moves from the compound to three branches — which is why `.pp-absent` and the two `div` rows share this file. And `&:is(a, button)` pins the other direction, where the compound IS reachable and the unreachable BRANCH `a` is what upstream reports.
