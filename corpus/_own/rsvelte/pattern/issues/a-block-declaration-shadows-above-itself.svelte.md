# `a-block-declaration-shadows-above-itself.svelte`

**Issue:** shadow probe

Upstream resolves a reference against a scope that already holds every declaration of its block, so a local shadows the component's binding *above* its own declaration too. `ast_state_transform.rs` registered a name when the walk reached the declarator, so `const a = typeof v; function v() {}` read `typeof $.get(v)` — and the same for `let`, `var` and `class`, which is why the pre-pass registers all four rather than only the genuinely hoisted `function` / `var`. The registration is one method shared with the walk, and the `$props()` guard is extracted from the rewrite that owns it, because a pre-pass that registered a destructured prop would shadow the prop itself. `tdz()` covers the three kinds whose read is a TDZ error and must still resolve to the local; `sibling()` is the positive control — it reads the same two names from a function that declares neither. Ablated: 6 comparisons for the variable half, 6 for the function/class half, 12 with the pre-pass removed. Its first draft also found an unrelated live defect it does not gate — rsvelte wraps `console.log(a)` in `$.log_if_contains_state` for a handler-LOCAL `a`, where official wraps only a component binding — so the handler here writes `base` instead. 0 of 34,728 corpus entries move.
