# `leading-comment-ignore-reaches-a-post-pass-warning.svelte`

**Issue:** warning probe

Upstream snapshots the whole ignore STACK per node (`ignore_map.set(node, get_ignore_snapshot())`, `2-analyze/index.js:100-134`), so an ignore pushed for the enclosing `Program` — an HTML comment before the `<script>` — is still in force for a warning raised much later. `non_reactive_update` is raised from a POST-PASS over `instance.scope.declarations` (`2-analyze/index.js:737-777`), not from a visitor, and rsvelte's `variable_declarator` stored only `collect_ignore_codes_from_parent`, which reads the JS comments inside the script and never the stack. So the comment silenced every warning raised while walking and none raised afterwards. This file also pins the nearest-only rule from the other direction: the further comment carries a DIFFERENT code, so a port that unions the run of preceding comments instead of taking the last one passes the silencing half and fails nothing else here — its sibling file is what catches that. Measured on the 80-entry warning ratchet: entries with a code divergence 15 → 14 and the `non_reactive_update` bucket 3 → 2; on a 6-cell grid against the official compiler, 4/6 before and 6/6 after, with all four movements in the two cells official silences and the four it warns on unmoved.
