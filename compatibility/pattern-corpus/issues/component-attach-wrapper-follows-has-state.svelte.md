# `component-attach-wrapper-follows-has-state.svelte`

**Issue:** [#4751](https://github.com/baseballyama/rsvelte/issues/4751)

Upstream wraps a component `{@attach}` as `($$node) => (expr || $.noop)($$node)` only when the expression `has_state`, and drops `|| $.noop` when `scope.evaluate(expr).is_function`. rsvelte wrapped on `has_state || has_call` using Phase 2's metadata, whose `has_state` also counts state read inside a nested function body (upstream's `visit_function` enters bodies with `expression: null`). So every inline arrow that called something, such as `(el) => el.focus()`, was wrapped. Neither available answer is upstream's: Phase 2's over-counts function bodies, and the template walk component attributes use over-counts bindings blocked by a top-level `await`. The decision now takes their intersection, plus the non-pure-call flag, plus Phase 2's answer when the expression assigns outside any function body (the template walk does not read assignment targets). `|| $.noop` follows a port of `is_function`, and the expression is always transformed, as upstream always visits it. The rows cover an inline arrow with a call, an imported function, a stateful member, a ternary of arrows over a never-reassigned `$state`, an arrow whose body reads state, a call with and without a state argument, a local function, a `$state` function, a logical guard, a declaration, a function expression that writes state, a ternary of two bindings, and an assignment to state, which a first version that used only the template walk unwrapped.
