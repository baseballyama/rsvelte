# `4121-bind-this-each-scope-const.svelte`

**Issue:** [#4121](https://github.com/baseballyama/rsvelte/issues/4121)

A `bind:this` whose subject reads a `{@const}` declared in an each block. Upstream's `build_bind_this` collects each-block ids by walking the subject and asking `scope.get(name)` whether the binding's **declaration scope** is the each block's, so a `{@const}` there becomes a callback parameter; rsvelte keyed on the loop-variable **names** instead, so `k` was never collected and the setter read a stale signal. Three divergences in one walk, all in the same direction once the guards are ported together: the name-vs-scope key, an `_ => {}` that skipped eleven expression kinds (`\|\|`, template literal, object, `new`, unary, update, tagged template, chain, `await`, spread, `void`) and so meant "did not look" rather than "nothing here", and `seen` — upstream pushes the name **before** `is_reference`, so a non-reference occurrence burns it for every later one. Cells a–f fix the subject and vary the declaration's scope (each body, one `{#if}` deeper, declared shallow and used deep, no each at all, the loop variables themselves, an instance-scope `$derived` that must NOT be collected); g–j vary the subject's **shape** at a fixed scope, which is the axis the grid held constant — `k \|\| 0` and `` `k${k}` `` are the walk arms, and `{ k: k }.k` versus `{ kk: k }.kk` is the `seen`-order pair: the first collects nothing because the property key burned the name, the second collects because the key is spelled differently.
