# `4107-await-block-binding-shadows-a-prop.svelte`

**Issue:** [#4107](https://github.com/baseballyama/rsvelte/issues/4107)

An `{#await … then X}` / `{:catch X}` binding shadowing a prop of the same name. Upstream shadows by overriding `state.transform[name]`, and rsvelte registered that transform too — but a non-source prop never reaches `state.transform`: the identifier arm returns `$$props.name` early, guarded only by `shadowed_prop_names`, which `each_block`, `snippet_block` and `const_tag` all populate and the await visitor did not. The `other = 1` row is the axis that made this look narrower than it is: a default makes the prop a SOURCE, so its read falls through to the transform and was always correct. The controls are a non-colliding `then value`, an `{#each}` item shadowing the same prop, and the top-level `{code}` / `{rest.x}` placed BEFORE every block — without those the fix reads as "never read the prop". The top-level read is deliberately not placed AFTER a `{:catch}`: upstream clones `transform` for `then_context` and not for `catch_context`, so a catch binding's override leaks past its block there and that is a separate divergence in the opposite direction.
