# `acorn-unchecked-ts-grammar-rule-in-a-template.svelte`

**Issue:** [#4084](https://github.com/baseballyama/rsvelte/issues/4084)

OXC ports TypeScript grammar checks acorn-typescript does not implement, so upstream compiles programs OXC reports on; `ACORN_UNCHECKED_TS_GRAMMAR_RULES` already listed 17 such codes and was read by the two script-side sites only. TS2368 was missing from the table AND the template, attribute, snippet-parameter and statement probes each asked OXC directly, so the same source compiled in a `<script>` and was a `js_parse_error` in `{…}`. Fixing either half alone reads as done: with the code added and the probes untouched, `{<string>() => a}` emits `p.textContent = ;`, which no JS parser accepts. The hosts here are crossed deliberately — one file, because a repro carrying only the reported template position cannot separate a fix that reaches one probe from one that reaches all of them. The trailing `{(<T,>(t: T) => t)(1)}` is the control: a legal generic arrow reaches the same probes and must be untouched. The **script**-side control lives in `crates/rsvelte_core/tests/acorn_unchecked_ts_grammar_hosts_4084.rs` (`script`, `script_module`) and deliberately not here: a `<string>() => a` inside `<script lang="ts">` is copied into the TSX shadow, where rsvelte writes `<string,>` and upstream copies it verbatim — a svelte2tsx defect this file would otherwise be the only carrier of, tracked separately. Removing that one line makes the shadow byte-identical and moves no compiler cell.
