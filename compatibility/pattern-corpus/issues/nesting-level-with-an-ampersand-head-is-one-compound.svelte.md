# `nesting-level-with-an-ampersand-head-is-one-compound.svelte`

**Issue:** css-prune probe

`build_parent_chains` links each nesting level to the one below it with `with_descendant_head`, which is right for `.g { .a { … } }` and wrong for `.box { &:disabled + .el { … } }`: a level whose head compound carries a `&` names the SAME element as the level below, so it has to be folded into that compound rather than hung off it as a descendant. It never even got that far — `structural_simple_selector_is_evaluable` has no `NestingSelector` arm, so such a level was discarded whole, `build_parent_chains` returned `None`, and the sibling matcher fell back to a compound-only `Info` that resolves `&` to nothing and prunes. Three levels are the minimum: `.box:disabled + .el { & + .lab }` is fine at one, because that level's `&` is in the CURRENT rule where a separate substituting path already handled it. Fixing the fold alone leaves `.a { & { & + .a2 } }`, whose merged chain is one compound and is dropped by the `len() >= 2` filter, so the `Info` path resolves `&` through the same `nesting_substitute_alternatives` the argument-list substitution uses — one answer to "what does `&` stand for" instead of two. The `:has()` row is not decoration: that unification made a level `build_parent_chains` DECLINES (`:has` is deliberately non-evaluable) resolve to nothing instead of to the parent's own compounds, which turned `svelte-put/sites/docs/…/+layout.svelte` from passing to over-reporting — a regression the 80-entry ratchet did catch, one run after the grid was green. Measured on that ratchet: entries with a code divergence 12 -> 9 and the over direction 6 -> 3, all three huly `Modern*` components; on a 24-cell grid against the official compiler, 19/24 before and 24/24 after, with emitted CSS byte-identical on all 24. Ablated, this file reports three selectors official keeps while its seven negatives are unchanged.
