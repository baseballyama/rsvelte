# `console-wrap-evaluates-an-unwritten-let.svelte`

**Issue:** evaluate probe

Upstream wraps a dev `console.<method>` only when an argument is a spread or `scope.evaluate(arg).has_unknown`, and its identifier case evaluates a binding's initializer when **`!binding.updated`** — the test is whether the name is ever written, not whether it is `const`. `console_wrap.rs` collected verdicts only from a `const` declaration, so `let plain = 1; console.log(plain)` was wrapped where official emits the bare call, and so was the `var` form. The controls are the whole point and all four must keep the wrap: a `let` later assigned, a `let` incremented, a `let` with no initializer (upstream's `binding.initial === null`), and a read of the component's own `$derived`. Ablated back to the const-only rule the repro fails and the 116-comparison grid goes 5 -> 7. 0 of 34,728 corpus entries move, on a napi checked to carry the change — no collected component logs an unwritten local `let`. What the grid still leaves open is two more sub-causes of the same predicate: a **template** handler's locals are invisible to `args_need_wrap` entirely (it evaluates against the component scope with no local bindings), and a global call such as `Math.random()` is `NUMBER` to upstream's globals table and UNKNOWN here.
