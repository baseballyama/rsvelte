# `import-attributes-are-parsed-not-assumed-empty.svelte`

**Issue:** parse-ast probe

`ImportDeclaration.attributes` and `ExportNamedDeclaration.attributes` were hardcoded to `IdRange::empty()` and the second argument of a dynamic `import()` to `options: null`, so a `with { … }` clause and an import's options were **dropped from `parse()` while the source plainly wrote them** — official reports one `ImportAttribute`, rsvelte reported none. There was no `ImportAttribute` node at all, which is why the field could not be populated rather than merely was not: the fix adds the variant, the `with_clause` conversion, the raw-envelope tag and its JS reader. Nothing but the parse-AST gate can see it — `compile()` output is byte-identical on all four targets, and it stays so because the second argument is populated on the PROGRAM conversion only, leaving the codegen path's node exactly as it was. The controls are the two shapes that already worked and must not move: an `import` with no clause keeps `attributes: []` (acorn writes it), and a bare `import()` keeps `options: null`. The string-key and two-entry rows are here because a converter that assumes an identifier key, or stops after one entry, passes the first row alone. Measured: three keys per axis pre-fix, zero post-fix; over a 4,898-unit x 2-axis parse sweep the fix removes four distinct keys and **adds none**, with compile output identical over 14,694 pairs. Its sibling carries the TypeScript half, which needs a separate file because `lang` is per script.
