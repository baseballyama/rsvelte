# `a-wholly-global-nested-rule-survives-an-unused-parent.svelte`

**Issue:** css-prune probe

A rule whose whole selector is `:global(...)` matches elements this component does not own, so an unused ancestor cannot make it unused — upstream keeps it used and prints the ancestor `(unused)`, where rsvelte let `is_parent_chain_unused` kill it and printed `(empty)`. The skip existed but sat in the final per-simple-selector loop, which the parent-chain check returns before ever reaching, so the guard was unreachable for exactly the inputs it was written for. Both halves are observable: the nested rule got a `css_unused_selector` warning official does not emit, AND the emitted CSS differed by one word. The line that has to be drawn is not "a selector mentioning `:global` is never reported" — `& :global(img)`, `:global(img).k` and `.absent :global(img)` are all reported by official, and they are here for that reason: a `:global` sharing its compound or its chain with a local part is judged as usual, only a lone one is exempt. Measured on the 80-entry warning ratchet: entries with a code divergence 9 -> 8, and the `css_unused_selector` OVER direction to zero; on an 11-cell grid against the official compiler, 6/11 before and 11/11 after, with emitted CSS 7/11 before and 11/11 after. Ablated, this file emits five warnings official does not and its CSS stops matching, while all fourteen expected reports are unchanged.
