# `an-export-star-reaches-the-program-body.svelte`

**Issue:** parse-ast probe

`convert_statement_for_program` had no `ExportAllDeclaration` arm, so `export * from './m.js'` fell through `_ => None` and **the statement vanished from `parse()`'s program body** — official four elements, rsvelte one. `compile()` keeps the re-export, so nothing that reads generated text can see this; the loss is confined to `parse()`, `svelte2tsx` and `rsvelte-lint`, which all read that body. It also had a compensating hack: the TS-namespace conversion substituted a `DebuggerStatement` for exactly this statement so `remove_typescript_nodes` would not judge the namespace type-only, and that stand-in is now unnecessary. The four rows are the four shapes: bare, `as ns` (the `exported` slot), a `with` clause (`attributes`, which shares its converter with the import family above), and a sibling `export { named } from` that must stay an `ExportNamedDeclaration` — without it the walk compares rsvelte's surviving named export against official's first element and reports a `type` mismatch that stops the diff, which is what the pre-fix measurement shows. **The output gate could never have caught the neighbouring defect this file also exposes**: official prints `export *  from` with two spaces and rsvelte with one, on all four targets, and the comparison-side oxfmt pass collapses the difference — measured on both spellings, not assumed. Measured: two keys per axis pre-fix, zero post-fix; a 41-construct x plain/`lang="ts"` grid drops from 12 cells carrying 6 distinct keys to 8 carrying 4; compile output byte-identical over 14,694 pairs and normalization-equal on all four targets for this file; svelte2tsx TSX byte-identical with no map violations; `rsvelte-fmt` matches the oxfmt oracle. Whether this moves the ratchet's `Program.body[]#length` is **unmeasured** — no `.svelte` in `submodules/svelte` carries the shape, so only a collected-corpus run can say.
