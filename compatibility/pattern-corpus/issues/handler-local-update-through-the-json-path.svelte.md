# `handler-local-update-through-the-json-path.svelte`

**Issue:** shadow probe

The client lowers an `UpdateExpression` in **three** places — the typed arm of `convert_js_node`, `try_transform_update`, and `convert_update_expression` (the JSON path). The first two refuse a name whose reference at that position belongs to a plain local (`reference_is_plain_local`); the third went from `extract_identifier_name_from_json` straight to `context.state.transform.get(&name)`, so `var v = 0; while (v < 1) { v++; }` in a template handler, in a component that also has `let v = $derived(base)`, emitted `$.update(v)` against the component's signal. Finding the third port needed a `Backtrace::force_capture()` in `b::svelte_call`: instrumenting the two known call sites and all five `format!("$.update(…)")` producers reported nothing. Ablated: 2 of 4 here, 4 of 6 on the 16-cell grid. 0 of 34,756 corpus entries move. A `var` declared in a `for` HEAD is a **separate, open** cause and is deliberately not in this file — phase 2 creates the local binding but leaves its reference list empty while the component's `Derived` binding owns the handler's positions, so a position-keyed test cannot separate them in any of the three ports.
