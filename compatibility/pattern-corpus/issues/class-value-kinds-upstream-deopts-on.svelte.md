# `class-value-kinds-upstream-deopts-on.svelte`

**Issue:** css-prune probe

Upstream's `gather_possible_values` (`2-analyze/css/utils.js:11-77`) is an ALLOW list: `Literal`, `ConditionalExpression`, `LogicalExpression` and — for a `class` — `ArrayExpression` / `ObjectExpression`. Every other node is `UNKNOWN`, which makes the attribute match every selector, so a rule stays. rsvelte's port added two arms upstream does not have — `TemplateLiteral` with no interpolation, and a `+` `BinaryExpression` — so `class={`a b`}` and `class={'a' + 'b'}` produced a concrete value where upstream deopts, and a sibling selector was pruned out of the emitted CSS. The pruned rule does not apply at runtime either, so this is byte parity with upstream rather than a rendering defect; the divergence is that upstream is deliberately conservative here. Measured on the 80-entry warning ratchet: 35 entries diverge on `css_unused_selector`, and removing the two arms takes that to 23 — 12 entries and 110 of 116 over-reported selectors, with the 17 under-reporting entries and their 32 selectors unmoved, which is the control showing only this cause moved. Every one of the 12 has a template-literal class attribute.
