# `let-directive-carries-an-empty-modifiers-array.svelte`

**Issue:** parse-ast probe

Every legacy-AST directive converter in `legacy.rs` emits `modifiers` — upstream's `Directive` shape carries the field whether or not that directive can take one — and `convert_let_directive` was the one of eight that dropped it, so `parse()`'s legacy axis returned a `Let` node missing a key official spells `[]`. Nothing but the parse-AST gate can see it: `compile()` output is byte-identical on all four targets before and after, with no warnings on either side, so the key (`legacy::Let.modifiers#missing`, one of the ratchet's `estree-fields` bases) is the entire observable. The three control directives are not decoration — `on:click|once|preventDefault` (non-empty), `use:action` and `transition:fade|local` pin the VALUE as well as the presence, because a port that filled the field by re-deriving modifiers from source text would pass the `let:` half and change theirs. Both hosts are here because `let:` is legal on a component and on `<svelte:fragment>`, and the fragment has to sit INSIDE the component: at top level both compilers raise `svelte_fragment_invalid_placement`, and the file would then compile to nothing at all — an error-parity unit the output gates never reach. Measured: one key on `legacy` and none on `modern` pre-fix, zero on both post-fix; over a 4,898-unit × 2-axis parse sweep the fix removed exactly this one distinct key and added none anywhere. svelte2tsx output byte-identical with no map violations, and `rsvelte-fmt` matches the oxfmt oracle (control: a deliberately mis-indented sibling that both sides rewrote).
