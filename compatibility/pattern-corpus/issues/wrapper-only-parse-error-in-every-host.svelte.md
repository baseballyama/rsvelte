# `wrapper-only-parse-error-in-every-host.svelte`

**Issue:** [#4083](https://github.com/baseballyama/rsvelte/issues/4083)

rsvelte parses a template expression by wrapping it as `(<body>\n)`, and that `(` makes OXC speculate an arrow parameter list. `accessor` and `declare` are parameter-modifier keywords there, so `{accessor satisfies string}` was a `js_parse_error` in every template host while the identical body compiled inside `<script>` — a diagnostic the wrapper produced and acorn never sees. The retry re-parses the body with a newline in place of the `(`: the same one byte, so every caller’s `-1` offset arithmetic still holds. The retry belongs on the conversion path alone: ablating it leaves every host rejected, while the same retry added to the error probe as well moves nothing — 200 generated cells and 142,900 corpus units byte-identical either way — so that second copy is not shipped. Without the conversion path the hosts stop rejecting and emit `p.textContent = ;` instead, which is the same shape #4084 records one probe over. The hosts are crossed in one file because a repro carrying only the reported mustache cannot separate a fix that reaches one host from one that reaches all of them. The last three rows are controls: `{s}` reads a `<script>` declaration of the same body, `{accessor as string}` is a second TS operator on the same name, and `{(accessor, declare)}` is a sequence whose own parentheses must still be parsed as the source wrote them. A **parenthesized** `(accessor satisfies string)` is deliberately absent: OXC aborts on it with no AST, so no retry can recover it, and it is [#4389](https://github.com/baseballyama/rsvelte/issues/4389) against `upstream_issues/4083-oxc-parenthesized-satisfies-with-a-modifier-name.md`.
