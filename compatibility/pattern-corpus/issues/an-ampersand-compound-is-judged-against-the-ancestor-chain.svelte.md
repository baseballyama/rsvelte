# `an-ampersand-compound-is-judged-against-the-ancestor-chain.svelte`

**Issue:** css-prune probe

`.cont { .tab { &.absent { … } } }` resolves to `.cont .tab.absent`, so the compound has to be satisfied by an element that is a `.tab` INSIDE a `.cont`. rsvelte judged it in `is_nesting_compound_unused`, which asks only whether SOME element in the component satisfies the immediate parent's compound plus the new one — and a `class="cont kind-{kind}"` div satisfies any class selector, so it answered yes for a rule anchored two levels above it. The structural walk that does verify ancestors already existed and refused the input: `resolve_explicit_nesting_chains` accepts a compound that is `&` ALONE, and `&.absent` fell to `level_is_structurally_evaluable`, which has no `NestingSelector` arm. It now accepts a `&`-headed compound and merges the extra selectors into the parent chain's subject, which is the same fold `build_parent_chains` uses one level up. The `.q &` control is the reason the acceptance is head-only: a TRAILING `&` is a second constraint on the subject rather than a spliced chain, and upstream keeps it even with no `.q` in the component. `&.selected` (a `class:` directive), `&.open` (a static class), `&button` and `&.tab` are the other four, each satisfiable by a real `.tab` under a real `.cont`. Measured on the 80-entry warning ratchet: entries with a code divergence 7 -> 5 and the under direction 5 -> 3, closing huly's EmojiPopup and BasePreview. Ablated, this file reports nothing where official reports two, with the five controls unchanged in both arms.
