# `server-bind-get-after-const.svelte`

**Issue:** [#4753](https://github.com/baseballyama/rsvelte/issues/4753)

For `bind:x={get, set}` on a component, the server transform hoists `var bind_get = …; var bind_set = …;` into the enclosing fragment. Upstream pushes them onto that fragment's `state.init` while visiting the component, so they follow the fragment's `{@const}` and snippet declarations (which are visited first). rsvelte prepended them to the fragment body, so they came before a `const` they close over. In an async `{@const}` group they belong between the hoisted declarations and `var promises = $$renderer.run(…)`. A dev `<svelte:element>`'s tag validation is pushed onto the same `init`, so it interleaves with the binds in source order, and an element whose children declare `{const}` (or whose attributes are async, or whose content is bound) keeps its own `init`. The rows cover a snippet body, an `{#each}` body whose second `{@const}` follows the first component in source, a component's own children, an `{#each}` body mixing `<svelte:element>` and a bind around a `{@const}`, and a `<div>` with a `{const}` child.
