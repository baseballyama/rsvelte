# `an-index-signature-carries-its-parameter-and-type.svelte`

**Issue:** parse-ast probe

A `TSIndexSignature` was emitted as a bare envelope — `type`, `start`, `end`, `loc` and nothing else — with a comment in `expression.rs` saying it would stay that way "until their parameter/modifier fields have an exact public-AST conversion". They already had one: `convert_type_annotation_adjusted` and `push_span_fields` are what every neighbouring TS builder uses, and the measurement that unblocked this was checking whether that machinery reproduces official's positions at all — a generic function's `typeParameters`, built the same way, diverges on **zero** keys. **A bare envelope passes every check short of a field-level diff**: the node is present, its type is right, its span is right, the file parses and compiles identically, and svelte2tsx is byte-identical. Only the parse-AST gate looks inside. Four rows because four things can each be wrong alone: the `parameters` entry is an `Identifier` whose span covers the whole `k: string` rather than the name (the test asserts its `end` equals the annotation's), the value `typeAnnotation` is a second field with its own span, `readonly` is present only when written, and a plain `size: number` member alongside must keep working — a converter that rebuilt the signature list would break it. Measured: three keys per axis pre-fix (`parameters`, `typeAnnotation`, `readonly`) and zero post-fix; over the 4,898-unit x 2-axis parse sweep exactly the four ratcheted keys leave and **none appears**, with compile output byte-identical over 14,694 pairs and the two NAPI surfaces agreeing on 12 of 12 probes. One neighbour is measured and **not** fixed: `class C { static [k: string]: number }` drops the member entirely (`ClassBody.body[]#length`), because a class element goes through two other converters — the same pair that drops a `static {}` block. It has no corpus carrier.
