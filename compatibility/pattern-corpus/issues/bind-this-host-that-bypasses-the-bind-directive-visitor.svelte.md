# `bind-this-host-that-bypasses-the-bind-directive-visitor.svelte`

**Issue:** warning probe

Upstream runs ONE `BindDirective` visitor for every host; rsvelte has a visitor per host, and `<svelte:element>`, `<svelte:component>` and `<svelte:self>` each call `walk_bind_expression` directly instead of going through `bind_directive::visit`. That visitor is where the `non_reactive_update` rule for `bind:this` lives — only a reference under an `{#if}` / `{#each}` / `{#await}` / `{#key}` needs state — and it is also where `in_bind_this` is set, the flag that stops the generic identifier walk from marking the read. So on those three hosts a top-level `bind:this` was marked unconditionally and warned. This is the SAME bypass as the component row of `bind-this-block-kinds-for-non-reactive-update.svelte`, one entry point over: fixing that one said nothing about these three, which is the argument for enumerating the callers of the bypassed function rather than the hosts a defect was reported against. `<svelte:self>` cannot sit at the top level, so the snippet arm is what reaches it — and a snippet is deliberately not one of the four blocks. Measured on the 80-entry warning ratchet: entries with a code divergence 5 -> 3, and the OVER direction to zero for the first time. Ablated, this file reports four `non_reactive_update` where official reports two, and the `{#if}` and `bind:value` rows are unchanged in both arms.
