# A mutated instance import loses reactivity when it touches either script-content boundary

For a mutated instance-script import in legacy mode, the official compiler emits
`$.reactive_import` only when the import declaration lies **strictly inside** the instance
script's content span. An import that starts at the first content byte or ends at the last
content byte is misclassified as a module-script import, so its wrapper is omitted.

```svelte
<script>import { v } from "./v.js";
function go() { v.x = 1; }</script>
<b onclick={go}>{v}</b>
```

With Svelte 5.56.10, the official client output has no `$.reactive_import`; rsvelte emits one.
The official output parses and runs, but a mutation through `go` does not trigger the imported
value's re-evaluation. This is therefore a runtime-correctness difference, not byte-only parity.

## The measured boundary matrix

Each row is one independently compiled program. The count is the number of
`$.reactive_import` calls in client output.

| layout inside `<script>...</script>` | official 5.56.10 | rsvelte |
|---|---:|---:|
| import begins at the first byte | **0** | 1 |
| one leading newline | 1 | 1 |
| one leading space | 1 | 1 |
| another statement precedes the import | 1 | 1 |
| first-byte import plus trailing newline | **0** | 1 |
| import is the last statement, with no trailing whitespace | **0** | 1 |
| the same last import plus one trailing space | 1 | 1 |

The one-space controls separate the two strict offset comparisons from newline handling. A
layout explanation based only on newlines is false: either one ordinary space or one preceding
statement is enough to flip the official result.

## Cause

In upstream `phases/3-transform/client/visitors/Program.js`, the import declaration has already
been hoisted to module scope. The compiler therefore distinguishes instance imports from module
imports with source offsets:

```js
const { start, end } = context.state.analysis.instance.ast;
const node = /** @type {ImportDeclaration} */ (binding.initial);
const is_instance_import =
	/** @type {number} */ (node.start) > /** @type {number} */ (start) &&
	/** @type {number} */ (node.end) < /** @type {number} */ (end);
```

The instance `Program` span is the script content. Thus `node.start === start` for the first
declaration and `node.end === end` for the last declaration. Either equality makes a genuine
instance import fail `is_instance_import`. Module imports remain outside this span, so the
comparison appears to work except at these two boundaries.

## What rsvelte does about it, and why

**Decision: do not reproduce.** rsvelte identifies the declaration from its binding scope and
keeps `$.reactive_import` independent of whitespace or statement order. The official output
silently drops a live update, so reproducing it would change runtime behavior rather than only
generated bytes.

`crates/rsvelte_core/tests/reactive_import_boundaries_3513.rs` pins both boundary defects, the
one-space controls, dev and non-dev output, and an unmutated-import negative control. If
upstream fixes its boundary test, this record and the deliberate-divergence test can be removed.

An upstream fix could make the comparisons inclusive (`>=` / `<=`). Better, it could retain
the binding's declaring scope across the hoist and avoid using source layout as a scope oracle.

Tracked in rsvelte issue #3513.
