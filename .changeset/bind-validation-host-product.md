Run the whole host-agnostic half of the `bind:` validation for every host, and decide "this element takes no arbitrary attributes" before any individual `bind:`. Upstream's `BindDirective` visitor validates the binding NAME against the parent and then runs one host-agnostic tail; rsvelte had an arm per element visitor and four of them held only part of it. `<svelte:element>` ran the name check alone, so `bind:clientWidth={o?.k}` compiled into `($$value) => o?.k = $$value` — output no JS parser accepts — and a shorthand `bind:clientWidth` wrote to an undeclared name; `<C>` / `<svelte:self>` / `<svelte:component>` skipped the getter/setter arm, so `bind:group={() => v, (nv) => (v = nv)}` became a getter/setter prop pair. In the other direction a second duplicate-attribute check in phase 2, for components only, lacked the `this` exemption the parser's copy has, so `<C bind:this={el} bind:this={el} />` was refused where the official compiler accepts it. And `<svelte:window|document|body>` validated a `bind:` before rejecting a spread, reporting `bind_invalid_target` where upstream reports `illegal_element_attribute` / `svelte_body_illegal_attribute`.
